# Rememzo v0.1: Single-Command Setup

## Status

Planned as the final task of v0.1, after memory tools, project tools, API-key
authentication, and tests are complete.

## Goal

A developer should be able to install Rememzo, start it as a persistent local
service, and receive everything needed to connect an MCP client with one setup
command.

The intended public setup experience is:

```bash
uvx rememzo setup
```

The command should finish by printing:

```text
Rememzo is ready!

MCP URL: http://127.0.0.1:8765/mcp
API key: rmz_************************

Save this key now. It will not be displayed again.
```

The user can then copy the MCP URL and API key into Codex, Claude, ChatGPT, or
another MCP client.

## Why Not Only `curl | sh`?

A shell installer is convenient on Linux and macOS, but it is not portable to
Windows. The installation and setup logic should live in the Python
`rememzo` CLI. Small shell and PowerShell installers may be added later as
platform-specific entry points.

## Setup Responsibilities

`rememzo setup` should:

1. Detect the operating system.
2. Create an OS-appropriate application-data directory.
3. Create the SQLite database in that directory.
4. Run all Alembic migrations.
5. Create the initial local user.
6. Generate the first API key.
7. Store only the API-key hash in the database.
8. Install Rememzo as a background service.
9. Start the service.
10. Verify the MCP endpoint with a health check.
11. Print the URL, one-time API key, and client configuration guidance.

## Platform Service Adapters

The CLI should provide one setup experience while using the platform's native
service manager internally:

| Platform | Background service |
| --- | --- |
| Linux | systemd user service |
| macOS | launchd agent |
| Windows | Windows service or Task Scheduler |

Platform-specific behavior should remain behind a small service-management
interface so the rest of the setup flow stays shared.

## Data Location

The database and runtime data must not live inside the cloned Git repository.
Use standard per-user application-data locations for each operating system.

The exact paths will be selected during implementation. A library such as
`platformdirs` may be used to resolve them consistently.

## Security Rules

- Bind to `127.0.0.1` by default.
- Generate API keys with a recognizable `rmz_` prefix and secure random data.
- Display the plaintext API key only once.
- Store only a cryptographic hash of the API key.
- Never write the plaintext key to logs.
- Do not expose Rememzo through a tunnel until authentication is enabled.
- Avoid placing secrets directly in service-definition files.

## Idempotency and Recovery

Running `rememzo setup` more than once must be safe. It must not:

- delete or recreate an existing database;
- silently generate a replacement API key;
- create duplicate users or services;
- overwrite configuration without warning.

If the original key is lost, the user should explicitly create a replacement
and revoke the old key.

Interrupted setup should be recoverable by running the command again.

## Planned CLI Commands

```bash
rememzo setup
rememzo status
rememzo start
rememzo stop
rememzo restart
rememzo logs
rememzo keys create
rememzo keys revoke
rememzo upgrade
rememzo uninstall
```

For repository development, provide an equivalent development flow such as:

```bash
uv run rememzo setup --dev
```

## Client Configuration Output

After setup, the CLI should print ready-to-copy examples for supported MCP
clients. Each example should use:

- the local MCP URL;
- API-key authentication;
- the configuration format expected by that client.

Client-specific formats should be kept separate from the core installer so
they can evolve independently.

## Packaging Strategy

1. Package Rememzo with a `rememzo` console entry point.
2. Make `uvx rememzo setup` the primary developer installation path.
3. Optionally provide `install.sh` for Linux/macOS.
4. Optionally provide `install.ps1` for Windows.
5. Consider standalone binaries only if requiring Python or `uv` becomes a
   meaningful adoption problem.

## v0.1 Acceptance Criteria

- A clean machine can complete setup using the documented command.
- Alembic creates or upgrades the database successfully.
- Rememzo starts automatically after reboot.
- Rememzo restarts after an unexpected process failure.
- The MCP endpoint is reachable on localhost after setup.
- The generated API key authenticates an MCP client successfully.
- The raw API key is not stored in the database or logs.
- Re-running setup preserves existing memories and credentials.
- Status, restart, logs, key creation, and key revocation work.
- Setup is verified on Linux, macOS, and Windows.

## Explicitly Out of Scope

- Hosted Rememzo deployment
- Organization and team management
- Automatic tunnel provisioning
- Semantic embedding-model installation
- Graphical setup application
